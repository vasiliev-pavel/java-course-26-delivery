# Пара 2. Методы на массивах

**Цель:** написать методы своего модуля и научиться делать коммит на каждый метод.

**Что сдаём:** Pull Request с методами своего модуля, ревью соседа, слияние с веткой напарника.

---

## Перед парой (дома)

Если репозитория у тебя ещё нет, сделай [Установку](../../README.md#установка-один-раз) из главного README.

Если есть, обнови его:

```bash
git switch main
git pull
```

Открой в IntelliJ файл `src/main/java/delivery/Cart.java` (любой модуль) и запусти его `main`. Должны напечататься строки `OK` и `FAIL`. Если запускается — всё готово.

## На паре

### Шаг 1. Узнай свой модуль

Преподаватель скажет, какой модуль твой. Список модулей и их коротких имён — в [главном README](../../README.md#модули).

### Шаг 2. Создай свою ветку

Имя ветки: `модуль-фамилия`, латиницей, маленькими буквами, через дефис.

```bash
git switch main
git switch -c cart-ivanova
```

Эта ветка — **твоя до пары 6 включительно**. Новую ветку на следующих парах создавать не нужно.

Проверь, что ты в своей ветке:

```bash
git status
```

Первая строка должна быть `On branch cart-ivanova`.

### Шаг 3. Прочитай свой файл

В файле модуля три блока:

| Блок | Что делать |
|---|---|
| `Задачи на пару` | обязательно, на паре |
| `Уровень B` | обязательно, если преподаватель сказал, что у тебя уровень B; иначе — если осталось время |
| `Домашка: интеграция` | дома, см. ниже. **На паре не трогай** |

Что должен делать каждый метод, написано в комментарии над ним. Сейчас внутри каждого метода стоит `// TODO` и «заглушка» — `return 0;`, `return -1;` и т. п. Её нужно заменить на настоящий код.

> Некоторые проверки показывают `OK` ещё до того, как ты что-то написал. Это совпадение: заглушка случайно вернула правильный ответ (например, 0 для пустой корзины). Метод всё равно нужно написать.

### Шаг 4. Пиши методы по одному

Для каждого метода из блока «Задачи на пару»:

1. Удали `// TODO` и заглушку, напиши код.
2. Запусти `main` своего модуля. Все проверки этого метода должны стать `OK`.
3. Посмотри, что изменилось, и сделай коммит:

```bash
git diff
git add src/main/java/delivery/Cart.java
git commit -m "cart: add cartTotal"
```

Формат сообщения: `модуль: add имяМетода`. Один метод — один коммит.

### Шаг 5. Уровень B

Если закончил обязательные методы, переходи к блоку «Уровень B». Коммиты такие же.

### Шаг 6. В конце пары

```bash
git log --oneline
```

Покажи вывод преподавателю. Там должны быть твои коммиты, по одному на метод.

## Как хранятся данные

Все данные лежат в `DeliveryData.java` в виде **параллельных массивов**: i-й элемент каждого массива относится к одному объекту.

- Всё про блюдо номер 2: `dishNames[2]`, `dishPrices[2]`, `dishRestaurant[2]`...
- **Деньги в копейках:** `34000` = 340,00 ₽.
- **Время в минутах от полуночи:** `600` = 10:00, `1320` = 22:00.
- **Город** — сетка клеток от (0, 0) до (10, 10).

Обращаться к данным так: `DeliveryData.dishPrices[i]`.

## Правила по коду

- Можно: `if`, циклы, свои вспомогательные методы, массивы, `length`, `charAt`, `equals`.
- Нельзя: `Math.*`, `Arrays.sort`, коллекции (`ArrayList`, `HashSet`...), стримы, рекурсию.
- Строки сравниваем через `equals`, **не** через `==`.
- Метод **возвращает** результат и ничего не печатает (`System.out.println` внутри метода не нужен).

## Домашка

### 1. Push и Pull Request — в течение двух дней после пары

```bash
git push -u origin cart-ivanova
```

(`-u` нужно только в самый первый раз. Потом хватит просто `git push`.)

Открой Pull Request:

1. Зайди в репозиторий на GitHub → вкладка **Pull requests** → **New pull request**.
2. **base:** `main`, **compare:** `cart-ivanova`.
3. Название: `cart: Иванова` (модуль и фамилия).
4. **Create pull request**.

Название своей ветки напиши в чат группы: оно понадобится напарнику.

### 2. Ревью соседа — до следующей пары

Проверь PR **следующего** модуля по кругу:

Меню → Корзина → Промокоды → Доставка → Время → Курьеры → Маршрут → Отзывы → Аналитика → Меню

(у Меню — Корзина, у Аналитики — Меню). Если следующий модуль никому не достался, бери через один.

Как оставить комментарий: открой PR → вкладка **Files changed** → наведи мышь на строку → синий **+** → напиши текст → **Add single comment**.

Оставь **3 комментария к строкам кода**:

1. на каких данных метод сломается (пустой массив, 0, граница диапазона, отрицательное число);
2. что непонятно или лишнее;
3. что понравилось.

### 3. Правки после ревью

Прочитай комментарии к своему PR. Исправь код, сделай коммит и `git push` — PR обновится сам. С чем не согласен, ответь в комментарии, почему.

### 4. Интеграция — до следующей пары

Метод из блока «Домашка: интеграция» использует метод **напарника** из другого модуля.

| Твой модуль | Берёшь метод у |
|---|---|
| Меню | Время (`Time.isOpen`) |
| Корзина, Отзывы | Меню (`Menu.findDish`, `Menu.cheapestInRestaurant`) |
| Промокоды, Доставка | Корзина (`Cart.cartTotal`) |
| Время, Курьеры, Маршрут | Доставка (`Delivery.distance`) |
| Аналитика | Отзывы (`Reviews.bestRestaurant`) |

Пока у тебя метод напарника — заглушка, твоя интеграция будет `FAIL`. Чтобы получить его настоящий код, влей ветку напарника в свою:

```bash
git fetch
git merge --no-edit origin/menu-petrova
```

`menu-petrova` замени на ветку напарника (из чата). Список всех веток: `git branch -r`.

Допиши свой метод интеграции, проверь, что проверки в блоке «Интеграция» стали `OK`, сделай коммит и `git push`.

> Напарник ещё не запушил ветку? Напиши ему. Если за день до пары ветки всё ещё нет, скажи преподавателю.

**Маршрут:** после слияния удали свой метод `dist` и везде используй `Delivery.distance`. Все проверки должны остаться `OK`. Это отдельный коммит: `route: use Delivery.distance`.

### 5. Проверь себя

```bash
git log --oneline --graph
```

Должны быть видны: коммиты по методам, правки после ревью и слияние с веткой напарника (строка `Merge remote-tracking branch 'origin/...'`).
